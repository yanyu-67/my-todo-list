# 待办事项管理系统需求文档

## 1. 文档说明

### 1.1 项目定位

本项目仅供学习使用，用于练习 Java Web 前后端分离项目的开发过程，重点学习 RESTful API、数据库持久化、用户认证、权限控制和 Vue 前端开发。

### 1.2 产品目标

实现一个面向 Java Web 网页端的个人待办事项管理系统。用户登录后可以管理自己的待办事项，查看任务统计，并通过搜索、状态筛选、日期筛选和重要事项筛选快速定位任务。

### 1.3 本期范围

本期只实现普通用户，不实现管理员、协作、共享和团队功能。系统只需要支持网页端使用，不要求移动端专门适配。

## 2. 技术与实现约束

- 后端使用 Java 21 和 Spring Boot 3.x。
- 使用 Spring MVC 实现 RESTful API。
- 使用 Spring Data JPA / Hibernate 访问 PostgreSQL，不在业务代码中直接拼接 SQL 作为主要实现方式。
- 使用 Spring Security 和 JWT 实现登录认证及接口权限控制。
- 前端使用 Vue 3、Vite、Vue Router、Pinia、Element Plus 和 Axios。
- 使用统一 JSON 格式返回成功和错误响应。
- 使用 JUnit 5 和 Spring Boot Test 测试后端功能。
- 只要求本地开发和运行，不要求 Docker、云服务器、Redis、消息队列或 CI/CD。

## 3. 用户与权限需求

### 3.1 用户类型

系统只有普通用户一种用户类型。每个用户只能访问和管理自己创建的待办事项，不能查看、修改或删除其他用户的任务。

### 3.2 注册

用户可以使用用户名和密码注册账号。

需求规则：

- 用户名必填，系统中必须唯一。
- 密码必填，长度至少为 6 位。
- 不需要昵称字段。
- 密码必须经过安全哈希后保存，不能明文保存。
- 注册成功后可以跳转登录页；是否自动登录不作为本期硬性要求，建议注册成功后要求用户登录。

### 3.3 登录

用户使用用户名和密码登录。

需求规则：

- 登录成功后，后端签发 JWT。
- 前端保存登录所需的 JWT，并在访问受保护接口时携带 `Authorization: Bearer <token>`。
- 用户名或密码错误时，返回统一格式的错误信息。
- 未登录用户不能访问任务管理接口。
- JWT 需要校验签名和有效期。

### 3.4 退出登录

退出登录由前端完成：清除本地保存的 JWT 和登录状态，然后跳转到登录页。

本期不要求服务端维护 Token 黑名单。对于需要立即失效的登录状态，可通过修改密码使原登录状态失效，并要求重新登录。

### 3.5 修改密码

登录用户可以修改自己的密码。

修改密码需要输入：

- 旧密码；
- 新密码；
- 确认密码。

需求规则：

- 新密码长度至少为 6 位。
- 新密码和确认密码必须一致。
- 旧密码校验失败时不能修改密码。
- 新密码不能以明文保存。
- 修改成功后，当前 JWT 失效，前端清除登录状态并跳转登录页，用户需要使用新密码重新登录。

## 4. 待办事项需求

### 4.1 数据字段

| 字段 | 类型建议 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | Long / UUID | 是 | 待办事项唯一标识，由后端生成 |
| `title` | String | 是 | 任务标题 |
| `description` | String | 否 | 任务描述 |
| `completed` | Boolean | 是 | 完成状态，默认 `false` |
| `important` | Boolean | 是 | 是否为重要事项，默认 `false` |
| `dueDate` | LocalDate | 否 | 截止日期，只精确到日期 |
| `createdAt` | DateTime | 是 | 创建时间，由后端生成，只读 |
| `updatedAt` | DateTime | 是 | 最后更新时间，由后端维护，只读 |
| `userId` | Long / UUID | 是 | 所属用户，由认证信息确定，不接受前端指定 |

### 4.2 状态

待办事项只有两种状态：

- 未完成：`completed = false`；
- 已完成：`completed = true`。

新建任务时默认为未完成。用户可以将未完成任务标记为已完成，也可以取消完成，将其恢复为未完成。

### 4.3 支持的操作

登录用户可以对自己的任务执行以下操作：

- 创建任务；
- 查看任务列表；
- 查看任务详情；
- 编辑任务；
- 标记为已完成；
- 取消完成；
- 删除任务；
- 搜索任务。

本期不提供批量创建、批量完成或批量删除功能。

### 4.4 创建与编辑规则

- 标题为必填项。
- 描述为选填项。
- 是否重要默认为否，用户可以在创建或编辑时修改。
- 截止日期为选填项，只精确到日期。
- 创建时间和更新时间由后端自动维护，前端不可修改。
- 新建和编辑任务均使用弹窗表单。
- 保存失败时需要向用户显示明确的错误提示，不能静默失败。

### 4.5 删除规则

- 删除任务前必须进行二次确认。
- 确认后直接永久删除，不采用软删除。
- 删除成功后，列表和统计数据需要同步更新。

### 4.6 搜索规则

- 搜索同时匹配任务标题和任务描述。
- 搜索默认只作用于当前用户的任务。
- 搜索结果应与当前页面的状态、日期或重要事项筛选条件正确叠加。
- 无匹配结果时显示明确的空状态。

## 5. 首页功能需求

首页以仓库中的界面截图为主要视觉参考，采用深色主题、左侧导航、内容区域和荧光黄绿色主操作色。

### 5.1 左侧导航

登录后显示以下导航：

- 我的任务：显示当前用户的全部任务；
- 今天：显示截止日期为今天的任务；
- 重要事项：显示被标记为重要的任务；
- 退出登录：清除 JWT 并返回登录页。

“今天”和“重要事项”页面继续支持全部、进行中、已完成状态筛选。

### 5.2 页面顶部

首页顶部显示当前页面路径或工作区信息，并提供“添加任务”入口。点击后打开添加任务弹窗。

### 5.3 统计卡片

统计数据按当前用户的全部任务计算，不受当前搜索和列表筛选影响。

- 未完成：当前用户未完成任务总数；
- 今日到期：截止日期为今天的任务数；
- 已完成：当前用户已完成任务总数；
- 完成率：已完成任务数 ÷ 全部任务数；
- 没有任何任务时，完成率显示 `N/A`。

### 5.4 任务筛选

任务列表支持以下状态筛选：

- 全部；
- 进行中：对应未完成任务；
- 已完成：对应已完成任务。

页面同时提供搜索输入框，搜索标题和描述。

### 5.5 任务列表排序

默认按以下规则排序：

1. 未完成任务优先；
2. 其次按截止日期升序；
3. 没有截止日期的任务排在有截止日期的任务之后；
4. 截止日期相同或都没有截止日期时，按更新时间倒序。

### 5.6 任务列表展示

任务列表至少展示：

- 完成状态；
- 任务标题；
- 截止日期；
- 是否为重要事项；
- 当前状态。

点击任务后打开任务详情抽屉。编辑任务继续使用编辑弹窗，删除操作需要二次确认。

页面需要处理以下状态：加载中、任务为空、搜索无结果、接口失败和网络请求中。

## 7. 接口需求草案

具体路径和字段可在开发阶段根据代码结构微调，但必须保持 RESTful 风格和统一响应格式。

### 7.1 认证接口

| 方法 | 路径 | 说明 | 是否需要登录 |
| --- | --- | --- | --- |
| `POST` | `/api/auth/register` | 用户注册 | 否 |
| `POST` | `/api/auth/login` | 用户登录并获取 JWT | 否 |
| `POST` | `/api/auth/change-password` | 修改当前用户密码 | 是 |

### 7.2 任务接口

| 方法 | 路径 | 说明 | 是否需要登录 |
| --- | --- | --- | --- |
| `GET` | `/api/todos` | 查询当前用户任务，可携带搜索和筛选参数 | 是 |
| `GET` | `/api/todos/{id}` | 查询任务详情 | 是 |
| `POST` | `/api/todos` | 创建任务 | 是 |
| `PUT` | `/api/todos/{id}` | 编辑任务 | 是 |
| `PATCH` | `/api/todos/{id}/complete` | 设置完成或未完成状态 | 是 |
| `DELETE` | `/api/todos/{id}` | 永久删除任务 | 是 |
| `GET` | `/api/todos/statistics` | 查询首页统计数据 | 是 |

### 7.3 统一响应

成功响应建议采用：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

错误响应需要包含 HTTP 状态码、业务错误码、可读的错误信息，并保持 JSON 结构统一。后端不得把堆栈信息直接返回给前端。

## 8. 非功能需求

- 后端必须在服务端完成 JWT 身份认证和资源权限校验，前端路由守卫只能改善用户体验。
- 所有任务查询、修改和删除必须以当前登录用户为过滤条件。
- 密码、JWT 密钥等敏感信息不能提交到版本库。
- API 参数需要进行服务端校验，不能只依赖前端校验。
- 核心业务、认证失败、未登录访问和用户数据隔离需要有自动化测试。
- 页面应优先保证 Java Web 桌面浏览器环境下的可用性。

## 9. 明确不做的内容

本期不实现以下功能：

- 管理员角色和后台管理；
- 多人协作、任务共享和权限邀请；
- 分类、标签、子任务、评论和附件；
- 批量操作；
- 邮件、短信、推送和定时提醒；
- 第三方登录；
- 移动端专门适配；
- Docker、云部署、Redis、消息队列和 CI/CD。

## 10. 需求验收标准

- 用户可以注册、登录、退出登录和修改密码。
- 用户密码至少为 6 位，并以哈希形式保存。
- 修改密码需要校验旧密码、新密码和确认密码，成功后要求重新登录。
- 用户只能管理自己的任务。
- 用户可以完成任务的创建、查看、编辑、完成状态切换、搜索和永久删除。
- 任务包含标题、描述、完成状态、重要标记、截止日期、创建时间和更新时间。
- 首页具备导航、统计卡片、状态筛选、搜索和任务列表。
- 新建/编辑使用弹窗，详情使用抽屉，删除使用二次确认。
- 任务列表排序和首页统计符合本文档定义。
- 前后端可以在本地按项目文档启动，核心功能和权限边界有测试覆盖。
