# 新增管理员功能（需求与验收文档）

## 1. 文档目的

本文档用于定义“新增管理员功能”的业务需求、接口要求与验收标准，作为产品与开发、测试的统一依据。

---

## 2. 需求描述

### 2.1 需求范围

本次需求范围仅包含以下 5 项：

1. 管理员登录。
2. 管理员查看用户列表。
3. 管理员禁用/启用用户。
4. 管理员将某个普通用户指定为管理员（并支持恢复为普通用户）。
5. 系统默认管理员为 `admin`。

### 2.2 角色定义

- 普通用户（`USER`）：仅使用个人任务相关能力。
- 管理员（`ADMIN`）：可访问用户管理能力。

### 2.3 业务规则

1. 仅管理员可访问用户管理接口。
2. 被禁用用户不可登录系统。
3. 用户列表查询不得暴露敏感字段（如密码哈希）。
4. 系统必须保证默认管理员 `admin` 可用。
5. 本期需求不包含管理员对他人任务的代管能力。

### 2.4 非目标

本次不包含：
- 多级角色体系（如运营、审计员）。
- 细粒度权限点配置（菜单级/按钮级）。
- 批量启用/禁用、批量授权。
- 审计日志与审批流程。

---

## 3. 接口要求描述

> 接口统一遵循现有 RESTful 风格与统一 JSON 响应结构（`ApiResponse`）。

### 3.1 鉴权与状态码要求

- 所有管理员接口路径前缀：`/api/admin/**`
- 认证要求：必须登录且角色为 `ADMIN`
- 状态码语义：
  - `401`：未登录或登录态无效
  - `403`：已登录但无管理员权限
  - `404`：目标用户不存在
  - `400`：请求参数不合法
  - `200`：请求成功

### 3.2 管理员登录（复用登录接口）

- **方法与路径**：`POST /api/auth/login`
- **说明**：管理员使用与普通用户相同登录入口。
- **请求参数**：
  - `username`（必填）
  - `password`（必填）
- **成功响应 data 最低要求**：
  - `token`
  - `username`
  - `role`（用于前端权限展示与路由控制）
- **失败要求**：
  - 用户被禁用时，返回明确失败信息，不允许登录。

### 3.3 查看用户列表

- **方法与路径**：`GET /api/admin/users`
- **权限**：仅 `ADMIN`
- **查询参数**：本期可不要求分页（若后续用户量增长可扩展）
- **返回字段要求（每条用户记录）**：
  - `id`
  - `username`
  - `role`（`ADMIN` / `USER`）
  - `enabled`（`true` / `false`）
  - `createdAt`
- **敏感字段约束**：不得返回 `passwordHash` 或同类敏感字段。

### 3.4 启用/禁用用户

- **方法与路径**：`PATCH /api/admin/users/{userId}/status`
- **权限**：仅 `ADMIN`
- **请求体要求**：
```json
{
  "enabled": true
}
```
- **业务要求**：
  - 可将目标用户设置为启用或禁用。
  - 用户不存在返回 `404`。
  - 参数缺失或类型错误返回 `400`。

### 3.5 指定/取消管理员权限

- **方法与路径**：`PATCH /api/admin/users/{userId}/role`
- **权限**：仅 `ADMIN`
- **请求体要求**：
```json
{
  "role": "ADMIN"
}
```
- **允许值**：`ADMIN`、`USER`
- **业务要求**：
  - 可将普通用户升级为管理员。
  - 可将管理员恢复为普通用户。
  - 用户不存在返回 `404`。
  - 非法角色值返回 `400`。

### 3.6 默认管理员要求

- 系统初始化后必须存在 `username=admin` 的管理员账户。
- 该账户应满足：
  - `role=ADMIN`
  - `enabled=true`
- 该要求属于系统初始数据约束，应在验收中可验证。

---

## 4. 前端交互要求

1. 登录成功后保存并使用 `role` 信息。
2. 仅 `ADMIN` 显示用户管理入口。
3. 非 `ADMIN` 用户直接访问管理员页面时，应拦截并给出无权限反馈。
4. 用户管理页至少支持：
   - 用户列表展示
   - 启用/禁用操作
   - 授予/撤销管理员权限操作

---

## 5. 验收标准

## 5.1 功能验收项

### A. 管理员登录

- 使用管理员账户登录成功。
- 登录返回中包含 `role=ADMIN`。
- 被禁用管理员无法登录。

### B. 用户列表

- 管理员可获取用户列表。
- 列表中包含 `id/username/role/enabled/createdAt`。
- 返回数据不包含密码哈希。

### C. 启用/禁用用户

- 管理员可将目标用户禁用，再启用。
- 被禁用用户登录失败；启用后可恢复登录。

### D. 管理员授权

- 管理员可将普通用户设为 `ADMIN`。
- 被授权用户重新登录后具备管理员访问权限。
- 管理员可将该用户恢复为 `USER`。

### E. 默认管理员

- 系统初始化后存在 `admin` 管理员账户。
- `admin` 可正常登录并访问用户管理接口。

## 5.2 权限验收项

- 普通用户访问 `/api/admin/**` 返回 `403`。
- 未登录访问 `/api/admin/**` 返回 `401`。

## 5.3 接口一致性验收项

- 管理相关接口响应结构与现有 `ApiResponse` 保持一致。
- 错误响应状态码语义符合本文档要求。

## 5.4 构建与测试验收项

```bash
cd backend
./mvnw test
```

前端至少通过：
