# 新增管理员功能手把手指导手册

本文是 `新增管理员功能.md` 的开发落地手册，面向编程新手。它会告诉你为什么要改、改哪里、怎么写代码、怎么验证。

## 1. 先理解本次要做什么

当前项目已经有：

- 注册、登录、修改密码。
- JWT 登录态。
- 登录后只能操作自己的任务。
- 前端会保存 token，并在请求头里带上 `Authorization: Bearer <token>`。

本次要新增：

- 用户有角色：`USER` 普通用户、`ADMIN` 管理员。
- 用户有状态：`enabled=true` 可登录，`enabled=false` 禁用后不可登录。
- 管理员能查看用户列表。
- 管理员能启用/禁用用户。
- 管理员能把用户设为管理员，也能恢复成普通用户。
- 系统启动后要保证有一个默认管理员 `admin`。

不要做的事情：

- 不做管理员代管别人任务。
- 不做多级角色。
- 不做批量操作。
- 不返回密码哈希。

## 2. 推荐实现顺序

建议按这个顺序做，出错时也更容易定位：

1. 后端 `User` 实体增加 `role` 和 `enabled` 字段。
2. 登录接口返回 `role`，并禁止禁用用户登录。
3. JWT 认证时把角色放入 Spring Security 权限。
4. Security 配置 `/api/admin/**` 仅 `ADMIN` 可访问。
5. 新增管理员接口：用户列表、修改状态、修改角色。
6. 新增默认管理员初始化逻辑。
7. 前端保存 `role`，增加管理员页面和路由守卫。
8. 写测试并运行后端、前端构建验证。

## 3. 后端实现

### 3.1 新增角色枚举

为什么要做：

- 角色只允许 `USER` 和 `ADMIN`。
- 用枚举比直接写字符串更安全，能减少拼写错误。

新增文件：

`backend/src/main/java/com/yanyu/todo/entity/UserRole.java`

```java
package com.yanyu.todo.entity;

public enum UserRole {
    USER,
    ADMIN
}
```

### 3.2 修改 User 实体

当前文件：

`backend/src/main/java/com/yanyu/todo/entity/User.java`

要增加两个字段：

- `role`：用户角色。
- `enabled`：用户是否启用。

核心代码示例：

```java
@Enumerated(EnumType.STRING)
@Column(nullable = false, length = 20)
private UserRole role = UserRole.USER;

@Column(nullable = false)
private Boolean enabled = true;
```

构造方法建议保持普通注册用户默认是 `USER`：

```java
public User(String username, String passwordHash) {
    this.username = username;
    this.passwordHash = passwordHash;
    this.role = UserRole.USER;
    this.enabled = true;
}
```

再补 getter 和 setter：

```java
public UserRole getRole() {
    return role;
}

public void setRole(UserRole role) {
    this.role = role;
}

public Boolean getEnabled() {
    return enabled;
}

public void setEnabled(Boolean enabled) {
    this.enabled = enabled;
}
```

知识点：

- `@Enumerated(EnumType.STRING)` 表示数据库里保存 `USER` / `ADMIN`，不要保存 `0` / `1`。
- 保存字符串更直观，以后枚举顺序变化也不容易造成数据错乱。
- `enabled` 使用 `Boolean` 或 `boolean` 都可以，本项目 DTO 判断参数缺失时用 `Boolean` 更方便。

### 3.4 修改 AuthService 登录逻辑

当前文件：

`backend/src/main/java/com/yanyu/todo/service/AuthService.java`

登录时需要增加两个规则：

- 如果用户被禁用，不能登录。
- 返回结果中包含角色。

在密码校验通过后增加：

```java
if (!Boolean.TRUE.equals(user.getEnabled())) {
    throw new AuthException(HttpStatus.UNAUTHORIZED, "账号已被禁用");
}
```

返回值改成：

```java
String token = jwtService.generate(user.getUsername());
return new AuthResponse(token, user.getUsername(), user.getRole().name());
```

注意：

- 禁用用户返回 `401` 比较合适，因为它不能获得有效登录态。
- 不要把 `passwordHash` 放进任何响应 DTO。

### 3.5 修改 JWT 认证过滤器，让 Spring Security 认识角色

当前文件：

`backend/src/main/java/com/yanyu/todo/security/JwtAuthenticationFilter.java`

现在过滤器只把 username 放进认证上下文，权限列表是空的：

```java
new UsernamePasswordAuthenticationToken(username, null, List.of());
```

管理员接口需要判断角色，所以要把角色转成 Spring Security 的权限。

增加 import：

```java
import org.springframework.security.core.authority.SimpleGrantedAuthority;
```

把查询用户和创建认证对象改成：

```java
userRepository.findByUsername(username).ifPresent(user -> {
    if (Boolean.TRUE.equals(user.getEnabled())) {
        var authorities = List.of(
                new SimpleGrantedAuthority("ROLE_" + user.getRole().name())
        );

        var authentication = new UsernamePasswordAuthenticationToken(
                username, null, authorities);

        SecurityContextHolder.getContext().setAuthentication(authentication);
    }
});
```

知识点：

- Spring Security 的角色判断通常使用 `hasRole("ADMIN")`。
- `hasRole("ADMIN")` 实际检查的是权限名 `ROLE_ADMIN`。
- 所以这里要写 `"ROLE_" + user.getRole().name()`。
- 禁用用户即使带着旧 token，也不应该继续通过认证。

### 3.6 修改 SecurityConfig，保护管理员接口

当前文件：

`backend/src/main/java/com/yanyu/todo/config/SecurityConfig.java`

在 `.authorizeHttpRequests` 里增加管理员路径规则。顺序很重要，应该放在 `.anyRequest().authenticated()` 前面：

```java
.requestMatchers("/api/admin/**").hasRole("ADMIN")
.anyRequest().authenticated()
```

完整位置示例：

```java
.authorizeHttpRequests(auth -> auth
        .requestMatchers(HttpMethod.OPTIONS, "/**").permitAll()
        .requestMatchers("/api/health").permitAll()
        .requestMatchers(
                "/api/auth/register",
                "/api/auth/login"
        ).permitAll()
        .requestMatchers(
                "/v3/api-docs/**",
                "/swagger-ui/**"
        ).permitAll()
        .requestMatchers("/api/admin/**").hasRole("ADMIN")
        .anyRequest().authenticated()
)
```

验证目标：

- 未登录访问 `/api/admin/users` 返回 `401`。
- 普通用户访问 `/api/admin/users` 返回 `403`。
- 管理员访问 `/api/admin/users` 返回 `200`。

### 3.8 新增 AdminUserService

新增文件：

`backend/src/main/java/com/yanyu/todo/service/AdminUserService.java`

```java
package com.yanyu.todo.service;

import com.yanyu.todo.dto.AdminUserResponse;
import com.yanyu.todo.dto.UserRoleUpdateRequest;
import com.yanyu.todo.dto.UserStatusUpdateRequest;
import com.yanyu.todo.entity.User;
import com.yanyu.todo.entity.UserRole;
import com.yanyu.todo.exception.AuthException;
import com.yanyu.todo.exception.ResourceNotFoundException;
import com.yanyu.todo.repository.UserRepository;
import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.List;

@Service
public class AdminUserService {
    private final UserRepository userRepository;

    public AdminUserService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }

    @Transactional(readOnly = true)
    public List<AdminUserResponse> listUsers() {
        return userRepository.findAll().stream()
                .map(this::toResponse)
                .toList();
    }

    @Transactional
    public AdminUserResponse updateStatus(Long userId, UserStatusUpdateRequest request) {
        User user = findUser(userId);
        user.setEnabled(request.enabled());
        return toResponse(userRepository.save(user));
    }

    @Transactional
    public AdminUserResponse updateRole(Long userId, UserRoleUpdateRequest request) {
        User user = findUser(userId);
        UserRole role = parseRole(request.role());
        user.setRole(role);
        return toResponse(userRepository.save(user));
    }

    private User findUser(Long userId) {
        return userRepository.findById(userId)
                .orElseThrow(() -> new ResourceNotFoundException("用户不存在"));
    }

    private UserRole parseRole(String role) {
        try {
            return UserRole.valueOf(role.trim().toUpperCase());
        } catch (IllegalArgumentException ex) {
            throw new AuthException(HttpStatus.BAD_REQUEST, "角色只能是 ADMIN 或 USER");
        }
    }

    private AdminUserResponse toResponse(User user) {
        return new AdminUserResponse(
                user.getId(),
                user.getUsername(),
                user.getRole().name(),
                user.getEnabled(),
                user.getCreatedAt()
        );
    }
}
```

知识点：

- `@Transactional(readOnly = true)` 用于只读查询。
- `@Transactional` 用于修改数据。
- `ResourceNotFoundException` 会被全局异常处理转成 `404`。
- 非法角色转成 `400`。

```java
package com.yanyu.todo.controller;

import com.yanyu.todo.dto.AdminUserResponse;
import com.yanyu.todo.dto.ApiResponse;
import com.yanyu.todo.dto.UserRoleUpdateRequest;
import com.yanyu.todo.dto.UserStatusUpdateRequest;
import com.yanyu.todo.service.AdminUserService;
import jakarta.validation.Valid;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PatchMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import java.util.List;

@RestController
@RequestMapping("/api/admin/users")
public class AdminUserController {
    private final AdminUserService adminUserService;

    public AdminUserController(AdminUserService adminUserService) {
        this.adminUserService = adminUserService;
    }

    @GetMapping
    public ApiResponse<List<AdminUserResponse>> listUsers() {
        return ApiResponse.success(adminUserService.listUsers());
    }

    @PatchMapping("/{userId}/status")
    public ApiResponse<AdminUserResponse> updateStatus(
            @PathVariable Long userId,
            @Valid @RequestBody UserStatusUpdateRequest request) {
        return ApiResponse.success(adminUserService.updateStatus(userId, request));
    }

    @PatchMapping("/{userId}/role")
    public ApiResponse<AdminUserResponse> updateRole(
            @PathVariable Long userId,
            @Valid @RequestBody UserRoleUpdateRequest request) {
        return ApiResponse.success(adminUserService.updateRole(userId, request));
    }
}
```

如果你的 `ApiResponse` 没有 `success` 静态方法，就参考现有 Controller 的写法，改成项目当前风格。例如：

```java
return new ApiResponse<>(0, "success", adminUserService.listUsers());
```

### 3.10 新增默认管理员初始化

为什么要做：

- 验收要求系统初始化后必须有 `username=admin` 的管理员账户。
- 不能只依赖 `application.yaml` 里的 `spring.security.user.name`，因为项目已经用自己的登录接口和数据库用户了。

新增文件：

`backend/src/main/java/com/yanyu/todo/config/DefaultAdminInitializer.java`

```java
package com.yanyu.todo.config;

import com.yanyu.todo.entity.User;
import com.yanyu.todo.entity.UserRole;
import com.yanyu.todo.repository.UserRepository;
import org.springframework.boot.CommandLineRunner;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Transactional;

@Component
public class DefaultAdminInitializer implements CommandLineRunner {
    private final UserRepository userRepository;
    private final PasswordEncoder passwordEncoder;

    public DefaultAdminInitializer(UserRepository userRepository,
                                   PasswordEncoder passwordEncoder) {
        this.userRepository = userRepository;
        this.passwordEncoder = passwordEncoder;
    }

    @Override
    @Transactional
    public void run(String... args) {
        User admin = userRepository.findByUsername("admin")
                .orElseGet(() -> new User("admin", passwordEncoder.encode("123456")));

        admin.setRole(UserRole.ADMIN);
        admin.setEnabled(true);
        userRepository.save(admin);
    }
}
```

新手提醒：

- 这里为了符合现有配置，默认密码示例使用 `123456`。
- 真实生产环境不要把默认密码写死在代码里，应该改成配置项或初始化脚本。
- 本项目是学习项目，可以先用这个方式完成验收。

```js
const ROLE_KEY = 'todo_role'
```

```js
const role = ref(localStorage.getItem(ROLE_KEY) || '')
```

```js
function setLogin(loginData) {
  token.value = loginData.token
  username.value = loginData.username
  role.value = loginData.role
  localStorage.setItem(TOKEN_KEY, token.value)
  localStorage.setItem(USERNAME_KEY, username.value)
  localStorage.setItem(ROLE_KEY, role.value)
```

```js
function clearLogin() {
  token.value = ''
  username.value = ''
  role.value = ''
  localStorage.removeItem(TOKEN_KEY)
  localStorage.removeItem(USERNAME_KEY)
  localStorage.removeItem(ROLE_KEY)
}
```

最后 return 里加上：

```js
return { token, username, role, isLoggedIn, isAdmin, setLogin, clearLogin }
```

### 4.3 新增用户管理页面

```vue
<script setup>
import { onMounted, ref } from "vue"
import { ElMessage, ElMessageBox } from "element-plus"
import { listUsers, updateUserRole, updateUserStatus } from "../api/admin"

const users = ref([])
const loading = ref(false)

async function loadUsers() {
  loading.value = true
  try {
    users.value = await listUsers()
  } catch (error) {
    ElMessage.error(error.response?.data?.message || '加载用户列表失败')
  } finally {
    loading.value = false

async function toggleStatus(user) {
  const nextEnabled = !user.enabled
  await ElMessageBox.confirm(
    `确定要${nextEnabled ? '启用' : '禁用'}用户 ${user.username} 吗？`,
    '确认操作'
  )

    await updateUserStatus(user.id, nextEnabled)
    ElMessage.success('操作成功')
    await loadUsers()
  } catch (error) {
    ElMessage.error(error.response?.data?.message || '操作失败')
  }

  const nextRole = user.role === 'ADMIN' ? 'USER' : 'ADMIN'

    '确认操作'

    await updateUserRole(user.id, nextRole)
    ElMessage.success('操作成功')
    await loadUsers()
  } catch (error) {
    ElMessage.error(error.response?.data?.message || '操作失败')
  }
}

onMounted(loadUsers)
</script>
```

### 4.4 新增管理员路由守卫

```js
if (to.meta.requiresAdmin && !authStore.isAdmin) {

```

建议完整守卫顺序：

```js
router.beforeEach((to) => {
  const authStore = useAuthStore()

  if (to.meta.requiresAuth && !authStore.isLoggedIn) {
    return { name: 'login', query: { redirect: to.fullPath } }
  }

  if (to.meta.requiresAdmin && !authStore.isAdmin) {
    return { name: 'todos' }
  }

  if ((to.name === 'login' || to.name === 'register') && authStore.isLoggedIn) {
    return { name: 'todos' }
  }
})
```

## 5. 数据库注意事项

如果你使用 JPA 自动更新表结构，新增字段可能会自动加到 `users` 表。

如果数据库没有自动更新，需要手动执行类似 SQL：

```sql
ALTER TABLE users ADD COLUMN role VARCHAR(20) NOT NULL DEFAULT 'USER';
ALTER TABLE users ADD COLUMN enabled BOOLEAN NOT NULL DEFAULT TRUE;
UPDATE users SET role = 'ADMIN', enabled = TRUE WHERE username = 'admin';
```

注意：

- PostgreSQL 的布尔值是 `TRUE` / `FALSE`。
- 已有用户默认应是普通用户。
- `admin` 必须是管理员且启用。

## 8. 常见错误排查

### 8.1 管理员登录成功，但访问管理员接口还是 403

重点检查：

- `JwtAuthenticationFilter` 是否设置了 `ROLE_ADMIN`。
- `SecurityConfig` 是否写了 `.requestMatchers("/api/admin/**").hasRole("ADMIN")`。
- 登录用户数据库里的 `role` 是否真的是 `ADMIN`。

### 8.2 前端看不到“用户管理”

重点检查：

- 登录接口是否返回 `role`。
- `auth.js` 是否保存了 `role`。
- `AppLayout.vue` 是否使用 `authStore.isAdmin` 控制菜单显示。

### 8.3 禁用用户还能继续用旧 token 访问接口

重点检查：

- `JwtAuthenticationFilter` 是否判断了 `user.getEnabled()`。
- 如果没有在过滤器判断禁用状态，旧 token 会继续被当成有效登录态。

### 8.4 用户列表返回了 passwordHash

重点检查：

- Controller 是否直接返回了 `User` 实体。
- 应该返回 `AdminUserResponse`，只包含 `id/username/role/enabled/createdAt`。

## 9. 最终验收清单

完成后逐项确认：

- 管理员 `admin/123456` 可以登录。
- 登录响应包含 `token/username/role`。
- `role=ADMIN` 的用户能看到用户管理入口。
- 普通用户看不到用户管理入口。
- 普通用户直接访问 `/admin/users` 会被前端拦回。
- 未登录访问后端 `/api/admin/users` 返回 `401`。
- 普通用户访问后端 `/api/admin/users` 返回 `403`。
- 管理员访问后端 `/api/admin/users` 返回 `200`。
- 用户列表没有 `passwordHash`。
- 管理员可以禁用用户。
- 被禁用用户不能登录。
- 管理员可以重新启用用户。
- 管理员可以授予和撤销管理员角色。
- `cd backend && ./mvnw test` 通过。
- `cd frontend && npm run build` 通过。
